SPECIFICATION:
# top_module

## Behaviour

Flit format (32-bit word): bits [30:29] give the flit type: 01 = header, 10 = tailer, 11 = idle,
00 = body. Bits [28:27] carry the virtual-channel (VC) number, 00 = VC1 to 11 = VC4. In a header flit,
bits [7:4] are the destination row and bits [3:0] the destination column. The idle word is 32'h6000_0000.

One 5-port virtual-channel router (ports link1, link2, link3, link4, core), each with four VCs.

- `clk` is the read and write clock everywhere. `clr` is the reset.
- Input side: each port's words (`data_in_<P>`) are buffered per VC (ip_link). `full_out_<P>_vck` is
  input VC k's full flag, sent back upstream.
- Each buffered packet is routed XY from its header's destination and `current_address` (row in [7:4],
  column in [3:0]): higher row goes to link1, lower row to link2, higher column to link3, lower column to
  link4, otherwise core. It requests that output port's controller. There is no U-turn: input link N
  never requests output link N, and input core never requests output core.
- Output side: each output port's controller (op_link1 to op_link4 for links, op_core for core)
  allocates one of its four output VCs per packet and picks one ready VC per cycle. A VC is ready when it
  has data and the downstream VC is not full (`full_in_<P>_vck`). It reads that input VC (read enables
  ORed per input VC across all output controllers), and the crossbar (op_data_path) sends the word on
  `data_out_<P>` with bits [28:27] replaced by the output VC number.
- With no grant on a port, `data_out_<P>` is an idle flit (see final_op_data).

## Reset

`clr` (active high) is the reset for every child. See the children's specs for which state resets
synchronously and which asynchronously.
