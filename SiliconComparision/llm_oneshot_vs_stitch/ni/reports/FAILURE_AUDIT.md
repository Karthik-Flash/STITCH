## Audit findings

- Constants tied to child output ports (new1 oneshot: rd_add, wr_add, wr_dir, rd_dir; new1 stitch: rd_add, wr_add, wr_dir, rd_dir; nidepack oneshot: c_rd, rd_add, wr_add, wr_dir, rd_dir; nidepack simloop: c_rd, rd_add, wr_add, wr_dir, rd_dir; nidepack stitch: c_rd). The spec calls these child ports "not used" or "left open" and lists each child's ports in order without their direction; several files say so in a comment ("left open, so it can be tied to a constant value"). The prompt asks for a module with exactly the given ports, so the verdict stays LLM_BUG; giving the direction of each child port in the spec would remove the reading.
- new1 (simloop): port-shift check: 18806 cycle-exact mismatches against the golden with the router_fifo shift corrected (controls 0 / 5643), equivalent False: the failure is not caused by the shift alone.
