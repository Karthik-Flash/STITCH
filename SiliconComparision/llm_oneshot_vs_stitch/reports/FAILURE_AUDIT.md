## Audit findings

- rr_arbiter (oneshot): the first error is the SystemVerilog keyword `priority` used as a net name (the evaluator compiles with -g2012). The loop feedback shows only that syntax error; with `priority` renamed, real errors remain (procedural assignment to a net), so the verdict stays LLM_BUG.
- rr_arbiter (simloop): the first error is the SystemVerilog keyword `priority` used as a net name (the evaluator compiles with -g2012). The loop feedback shows only that syntax error; with `priority` renamed, real errors remain (procedural assignment to a net), so the verdict stays LLM_BUG.
- rr_arbiter (stitch): the first error is the SystemVerilog keyword `priority` used as a net name (the evaluator compiles with -g2012). The loop feedback shows only that syntax error; with `priority` renamed, real errors remain (procedural assignment to a net), so the verdict stays LLM_BUG.
- asynch_comparator (simloop): exhaustive check {'mismatch_unreachable': 46, 'unreachable_llm_equals_spec': 14, 'unreachable_golden_equals_spec': 32}. The tb.v/tb_signoff.v drive random pointer pairs, including ones no FIFO reaches; the spec formula is not the golden there. Testbench not changed in this part.
- asynch_comparator (stitch): exhaustive check {'mismatch_unreachable': 46, 'unreachable_llm_equals_spec': 14, 'unreachable_golden_equals_spec': 32}. The tb.v/tb_signoff.v drive random pointer pairs, including ones no FIFO reaches; the spec formula is not the golden there. Testbench not changed in this part.
- demux_16: every arm declares the outputs in the ANSI header and again as `wire` in the body, then assigns them in `always @(*)` (iverilog: `'op1' has already been declared`). The spec states plain 1-bit outputs and a combinational one-hot function; nothing in the spec or testbench causes the failure.
- Data-clocked / gated-clock modules (gray_mod6, rr_arbiter, irs, round_robin_req, falling_edge_pulse_generator, memory, router_fifo): memory signs off clean in every arm; every other final either does not compile or fails a sign-off property (a spec rule), so none is decided by the secondary cycle-exact check. The loop testbench tb.v is cycle-exact for these modules too, so the feedback the loop sees is stricter than the sign-off verdict.
- router_fifo: C..K in every arm; the sign-off property `FIFO order: wrong word read` fails in every arm (see rows).
- Golden RTL (mesh tb reference): the hybrid_signoff meshes fail the cycle-exact mesh tb only through dff_asynch_clr, dff_synch_clr, dff_synch_reset, memory, routing_algo_mesh. Each is formally equivalent to its golden module (Yosys equivalence check; a negative control fails). The mismatch comes from the golden's blocking-assignment flops (q = d) racing in simulation; the LLM modules use nonblocking (<=) (routing_algo_mesh is combinational: the golden uses nonblocking assignments in an explicit-list always block, the LLM module `always @(*)`). With those swapped back to golden the mesh composes (diag_signoff_dropin_*). Golden blocking assignments in clocked blocks: dff_asynch_clr tasks/dff_asynch_clr/golden.v:10, tasks/dff_asynch_clr/golden.v:12; dff_synch_clr tasks/dff_synch_clr/golden.v:10, tasks/dff_synch_clr/golden.v:12; dff_synch_reset tasks/dff_synch_reset/golden.v:8, tasks/dff_synch_reset/golden.v:10; memory tasks/memory/golden.v:44, tasks/memory/golden.v:50, tasks/memory/golden.v:54, tasks/memory/golden.v:57 (reports/ASSEMBLY.md).
