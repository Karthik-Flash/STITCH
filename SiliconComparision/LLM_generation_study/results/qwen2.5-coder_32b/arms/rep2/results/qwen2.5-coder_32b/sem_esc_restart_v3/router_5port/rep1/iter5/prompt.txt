SPECIFICATION:
# router_5port

## Behaviour

Top level of a 5-port router for a 2D mesh network-on-chip, with one clock and wormhole switching. The five
ports are link1, link2, link3, link4 and core; this order (link1 first, core last) is used everywhere below.
Each port has an input side (`data_in_<port>`, `full_out_<port>`) and an output side (`data_out_<port>`,
`full_in_<port>`).

Flit format: bits [30:29] are the flit type: 01 = head, 00 = body, 10 = tail, 11 = idle (no flit). A packet is
a head flit, then any number of body flits, then a tail flit. Bits [7:4] and [3:0] of a head flit are the
destination row and column. `current_address` is this router's row (bits [7:4]) and column (bits [3:0]). An
output with nothing to send shows the idle flit 32'h6000_0000.

What the router does:

- Each input side buffers the non-idle flits arriving on `data_in_<port>` (up to 4) and raises
  `full_out_<port>` when 3 or more are stored, so the sender stops.
- The head flit of a packet chooses the output, row first: destination row greater than this router's row:
  link1; less: link2; same row and destination column greater: link3; less: link4; same column: core. The body
  and tail flits of the packet follow the same output.
- Each output serves the 4 other inputs round-robin. Once it sends a packet's first flit, it keeps serving that
  input until the packet's tail flit has left (wormhole switching): packets are never interleaved on an output.
- An output sends one flit per clock cycle, from a register, and only at a rising `clk` edge where its
  `full_in_<port>` = 0. In a cycle with nothing sent, its `data_out_<port>` is 32'h6000_0000.
- A packet never leaves by the port it came in on; such a request is never served.

Structure: 5 `input_port` instances (one per port, input side) and 5 `output_port` instances (one per port,
output side), all with the same `clk`, `reset` and (for the inputs) `current_address`.

- Input X: `data_in` = `data_in_X`, `full_out` = `full_out_X`. Its `req` names the output its front flit wants
  (bit 0 = link1, bit 1 = link2, bit 2 = link3, bit 3 = link4, bit 4 = core), and its `flit` is that front flit.
- Output Y: `data_out` = `data_out_Y`, `full_in` = `full_in_Y`. Its requesters 0 to 3 are the 4 inputs other
  than Y, in the port order with Y left out. For example, output link1's requesters 0 to 3 are inputs link2,
  link3, link4, core; output core's are inputs link1, link2, link3, link4. Requester i's `req[i]` is the bit of
  that input's `req` that names output Y, and `flit<i>` is that input's `flit`.
- Input X's `rd_en` is 1 when any output's `pop` bit for input X is 1 (the front flit of X is being sent).

What the two child modules do:

- `input_port`: buffers non-idle flits (4 flits; `full_out` = 1 at 3 or more); `flit` is the oldest stored
  flit; `rd_en` = 1 removes it at the next rising `clk` edge. `req` is one-hot: 0 when empty; for a head flit
  at the front, its row-first route; for a body or tail flit at the front, the route held from the packet's
  head flit (stored when that head flit was removed).
- `output_port`: 4 requesters; when free, picks one round-robin among those with `req` = 1; once it sends a
  flit, holds that requester until a tail flit is sent. It sends the selected requester's flit at a rising
  `clk` edge when that requester's `req` bit is 1 and `full_in` = 0; `pop` (one-hot, combinational) names the
  requester whose flit is sent at that edge. `data_out` is a register: the sent flit, or 32'h6000_0000 after an
  edge where nothing is sent.

## Reset

Synchronous, active-high `reset`, shared by all instances: at a rising `clk` edge with `reset` = 1 every buffer
becomes empty, every output becomes free with `data_out` = 32'h6000_0000, and every round-robin priority starts
again from requester 0.
