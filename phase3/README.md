# Phase 3: MPSoC composition + interpreter v3

Phase 3 tests STITCH on real multiprocessor hardware code. It repairs 11 defective modules (8 taken from the group's
MPSoC, 3 seeded RISC-V/NoC modules) under 5 feedback conditions, then splices the repaired modules back into the real
designs and re-synthesises them, to see whether leaf-level repair restores top-level synthesis.

**Status (2026-09-27).** First full run done: `results/phase3_run/`, 990 runs (6 models x 11 tasks x 5 conditions x
N=3, protocol `feedback_first_v2`), analysed in `evidence/phase3_run/PHASE3_RESULTS.md`.

**Final state (2026-10-14).** The final batch (control arm and qwen2.5-coder:32b) and the sign-off re-scoring are in
`evidence/phase3_final/PHASE3_FINAL.md`. The paper write-up is Section 9 of `../paper/overleaf/main.tex` (v10) and
Supplementary Material S8 in `../paper/overleaf/supplement.tex`. The earlier write-ups (`PHASE3_MPSOC.tex`, v7) are in
`../paper/archive/`. The full story of every phase is in `../docs/PHASES_EXPLAINED.md`; the cluster commands are in
`../docs/HPC_GUIDE.md`.

**New to this?** Read `docs/PHASE3_EXPLAINED.md` first; it assumes no hardware background.

## Source of truth

- Results: the `metrics.json` files under `results/<run>/`. `master_log.json` is a monitoring log (it keeps superseded
  error entries) and is not used for numbers.
- Numbers in prose: `evidence/<run>/PHASE3_RESULTS.md` and `phase3_analysis.json`. Never copy a number from memory
  or from `SUMMARY.md` into the paper.

## A new or revised run

1. Change the runner, tasks or interpreter on the laptop; run `python phase3/tests/run_tests.py` and
   `python phase3/runner/validate_tasks.py`.
2. On the HPC, give the run its own directory: `export P3_OUT=$BASE/results/<new_run>` before
   `sbatch phase3/hpc/phase3_run.slurm` and again before `phase3_compose.slurm` (both honour `P3_OUT`).
   Never reuse `results/phase3_run/`: the runner resumes into an existing directory and would mix protocols.
3. Download into `phase3/results/<new_run>/`, then run
   `python phase3/runner/analyze_phase3.py --results phase3/results/<new_run>`.
   Output lands in `phase3/evidence/<new_run>/`, next to (not over) the first run.
4. Copy the figures you use into `paper/figures/` and update the paper numbers from the new `PHASE3_RESULTS.md`.

Known quirk: `run_manifest_<model>.json` is overwritten each time a model's job resumes, so it records the last
invocation's toolchain only.
